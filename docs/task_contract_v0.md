# IronFlow 任务合同 v0（草案）

状态：Draft。未得到官方评分细则确认前，不作为最终比赛协议。

## 任务

第一阶段为多源工业时序预测，第二阶段为基于预测资源边界的发电调度优化。两阶段顺序执行，预测结果不能使用优化结果反推。

## 预测定义

| 项目 | 当前草案 |
|---|---|
| 时间键 | `datetime` |
| 采样粒度 | 15 分钟 |
| 预测目标 | `generator_1`、`generator_all` |
| 短周期 | t+15 至 t+120 分钟，共 8 步 |
| 长周期 | t+15 至 t+1440 分钟，共 96 步 |
| 预测形式 | 滚动起点、直接输出多步预测 |
| 主指标 | 官方定义的 1-MAPE |
| 辅助指标 | MAE、RMSE、按步长误差、工况分层误差、运行时长 |

## 信息合同

允许：

- 起点时刻及之前的煤气发生、用户消耗、气柜状态、历史发电负荷和历史发电耗气。
- 经过规则确认的时间周期特征。
- 赛事明确允许的已知外生电价信息。

禁止：

- 起点之后的任何观测值。
- 测试集未来目标或未来发电耗气量。
- 由测试标签反推的特征、阈值或模型选择。
- 外部数据、外部预训练权重和联网推理服务。

## 验证协议草案

- 禁止随机划分。
- 使用固定的滚动时间折。
- 每个折内，填补、缩放、特征选择和模型只在训练段拟合。
- 评估起点必须具备足够历史窗口，目标窗口不能越过可用标签边界。
- 最终内部留出集在候选冻结前保持封存。
