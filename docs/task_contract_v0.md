# IronFlow 任务合同 v0（草案）

状态：Draft，已吸收 2026-09-16 官方群答复；提交模板和底层评分实现仍待最终确认。

## 任务

第一阶段为多源工业时序预测，第二阶段为基于预测资源边界的发电调度优化。两阶段顺序执行，预测结果不能使用优化结果反推。

## 预测定义

| 项目 | 当前草案 |
|---|---|
| 时间键 | `datetime` |
| 采样粒度 | 15 分钟 |
| 预测目标 | `generator_1`、`generator_all` |
| 短周期 | t+15 至 t+120 分钟，共 8 步 |
| 长周期 | t+15 至 t+1440 分钟，共 96 步 |
| 预测形式 | 每 15 分钟滚动一个起点；每个起点直接输出多步预测；最终一次性提交完整宽表 |
| 主指标 | 官方定义的 1-MAPE |
| 辅助指标 | MAE、RMSE、按步长误差、工况分层误差、运行时长 |

## 信息合同

允许：

- 起点时刻 `t` 及之前的煤气发生、用户消耗、气柜状态、历史发电负荷和历史发电耗气。
- 官方群答复明确允许使用 `t` 时刻这一行已提供的全部字段，包括当前实际发电量；这不是授权读取 `t` 之后目标的通行证。
- 滚动推理时，前一预测起点已经输出的预测结果可以作为后续输入。
- 经过规则确认的时间周期特征。
- 赛事明确允许的已知外生电价信息。

禁止：

- 起点之后的任何观测值。
- 起点 `t` 之后的测试目标、发电耗气量或任何其他观测。
- 由测试标签反推的特征、阈值或模型选择。
- 外部数据、外部预训练权重和联网推理服务。

## 验证协议草案

- 禁止随机划分。
- 使用固定的滚动时间折。
- 每个折内，填补、缩放、特征选择和模型只在训练段拟合。
- 评估起点必须具备足够历史窗口，目标窗口不能越过可用标签边界。
- 最终内部留出集在候选冻结前保持封存。

## 初赛输出契约（已知规则）

- `input.csv`：UTF-8，包含 `datetime`、原始特征以及可选的特征工程字段；新增字段必须以 `feat_` 开头。
- `s_result.csv`：UTF-8，包含 `datetime`，以及 `generator_1`、`generator_all` 在 `t+15` 至 `t+120` 的 8 个偏移预测列。
- `datetime` 表示滚动预测起点，不是目标时刻；预测宽表需要完整覆盖起点、无缺行、无重复。
- 后期起点的部分目标可能超出公开数据范围，仍需按起点完整输出，评分脚本按目标偏移提取真实值。
- 初赛压缩包命名为 `teamname_gas_predict_prelim.zip`；每日最多提交次数和最终排行榜规则以赛事通知为准。
- 初赛总评分由数据校验与预处理 50%、短周期预测 50% 构成；数据质量项关注时间间隔、缺失、重复、异常、无效列和 `feat_` 特征字段。
