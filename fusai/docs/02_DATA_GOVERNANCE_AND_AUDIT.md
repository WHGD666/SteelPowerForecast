# 数据治理与已知审计事实

## 1. 数据分层

### raw

`data/raw/` 只保存官方原始文件的本地副本，不允许任何脚本写回。

每个文件必须登记：

- 相对路径。
- 文件大小。
- SHA-256。
- 编码。
- 行数、列数。
- 最小和最大时间戳。
- 是否来自官方 ZIP 及对应 ZIP 哈希。

### prepared

`data/prepared/` 保存完全由配置和代码生成的中间数据。每个版本必须有独立子目录和 manifest，不允许覆盖历史版本。

建议命名：

```text
data/prepared/round2_v3_<config-short-hash>/
```

### outputs

模型预测、OOF、模型文件和报告属于运行产物，只能进入 `outputs/<run_id>/`，不得放入 raw 或 prepared。

| 文件族 | 主要含义 |

| gas_user | 高炉、转炉等生产用户的优先煤气消耗 |
| gas_holder | 高炉煤气气柜状态 |
| load | 两个发电负荷目标和三类机组煤气消耗量 |

测试 `generator_1` 与 `generator_all` 共 28,800 个目标单元全部为空。旧初赛持久性目标特征在复赛不可用。

## 4. 已知时间缺口

- `Semi_gas.csv`、`Semi_gas_user.csv`：
  - 2025-08-27 18:09
  - 2025-09-09 08:23
- `Semi_gas_holder.csv`、`Semi_load.csv`：
  - 2025-08-27 18:09
  - 2025-08-27 18:10
  - 2025-09-09 08:23

处理原则：先补齐一分钟时间轴并生成缺失标记，再按仅历史可见的规则处理；不能因为缺口不在 15 分钟整点就静默丢弃。

## 5. 已知异常候选

| 字段 | 时间 | 数值/问题 | 初步判断 |
|---|---|---|---|
| air_heater_4 | 2025-06-25 14:24 | -59,324,236,000 | 明显坏值 |
| converter_user1 | 2025-08-14 13:29 | -999 | 疑似异常哨兵值 |
| blast_furnace_gas_holder_1 | 2025-09-24 19:06 | 约 1.8e30 | 明显坏值 |
| blast_furnace_gas_holder_1 | 2025-09-24 19:07 | 极小负值 | 明显坏值 |

异常处理必须满足：

- 规则只在训练折拟合。
- 保留异常标记。
- 不把真实停机、减产和工况切换误删为异常。
- 修正前后数量、时间和原因写入 manifest。

## 6. 部分投运字段

旧配置错误地将以下字段视为全空：

- `blast_furnace_3`：2025-09-02 14:23 后有数据。
- `air_heater_3`：2025-05-14 10:27 后有数据。
- `blast_furnace_gas_holder_1`：2025-09-24 18:25 后有数据，测试期完整。

只有 `converter_user3` 在当前复赛训练和测试中全空。

部分投运字段不能简单删除，应同时建模：

- 当前数值。
- 是否已投运。
- 距离投运时间。
- 缺失/未投运状态。

## 7. 物理字段风险

- 旧高炉煤气发生合计遗漏 `blast_furnace_3`。
- 旧热风炉消耗合计遗漏 `air_heater_3` 和 `air_heater_5`。
- 一号气柜测试值约 0–27，与公开容量单位不一致，可能是匿名化、压力或缩放信号，禁止未经验证直接换算为 m³。
- 二号气柜测试范围约 0–175,055，与 20 万容量答疑较为一致，但仍需结合零值和停运状态分析。

## 8. 分布漂移

测试期相对九月末已观察到明显过程变量漂移，包括：

- `air_heater_5` 均值显著抬升。
- `blast_furnace_3` 工况变化。
- 二号气柜平均柜位抬升。
- 转炉煤气机组消耗下降。
- 高炉煤气机组消耗上升。

测试期覆盖国庆假期，所有正式验证报告必须包含：

- 日期/星期分层。
- 负荷高低工况分层。
- 炉体投运状态分层。
- 气柜状态分层。
- 正常日、周末和特殊减产时段分层。
