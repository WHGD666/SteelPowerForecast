## 结论

实验 `20261005T083741Z_sequence_gru_g1_c325928f68` 完整运行且工件验收通过，
但没有通过预登记门禁，不生成提交包，也不继续扫描 epoch、网络宽度、历史窗、
损失函数、种子或融合比例。

固定候选 `25% GRU + 75% shared tree` 相对控制只提升 **0.006482** 个百分点，
实质上等于持平，远低于 0.8 个百分点晋级门槛；8 月十日块退化
**1.184428** 个百分点。独立 GRU 比 shared tree 总体低 **1.911511** 个百分点，
说明完整 24 小时序列在当前信息合同下没有形成可稳定迁移的未来调度信号。

## Horizon 诊断

融合候选相对控制：

- 15–120 分钟：-0.034405 pct；
- 135–360 分钟：-0.276029 pct；
- 375–720 分钟：-0.033055 pct；
- 735–1440 分钟：+0.127236 pct。

只有最远端形成小幅正收益，而中近端均退化。独立 GRU 在四段都明显弱于控制，
因此不能把这一现象解释为模型已经学到稳定的 24 小时轨迹。

## 训练稳定性与失败机制

四折训练 loss 均正常下降，30 epoch 最终值依次为 0.207846、0.184909、
0.186263 和 0.169258；运行使用 CUDA，未发生数值异常或提前终止。训练 loss 下降
只能证明模型拟合了各折训练分布，不能证明它识别了伪测试期的调度制度。

本次失败更可能来自任务的信息边界，而不是训练故障：

1. 相同的历史过程轨迹之后，未来发电调度仍可能由未提供的计划、检修和人工决策驱动；
2. 只有 5,474–12,962 个训练 origin，却要一次估计 96 维未来轨迹，深度模型方差较高；
3. 不允许使用真实发电目标历史，GRU 缺少通常最强的自回归状态；
4. 8 月和 9 月下旬的反向表现说明制度变化无法由继续训练或单纯扩大网络解决。

因此不应事后增加 epoch、hidden size 或种子来追逐四块验证结果。
