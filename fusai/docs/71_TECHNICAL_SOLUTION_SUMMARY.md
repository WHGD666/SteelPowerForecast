# 技术方案总结（实验报告骨架）

> 本文件按"问题 → 数据 → 信息边界 → 特征 → 验证 → 模型 → 门禁 → 工程保障 → 结论"
> 组织复赛的完整技术方案。每个小节末尾标注可展开引用的详细文档，供撰写最终实验
> 报告时按图索骥。数字均与机器登记簿一致。

## 1. 问题定义

- 赛题：钢铁企业煤气发电负荷预测（AIC 2026 AI+钢铁赛道，IronFlow）。
- 输出四块：短周期未来 2 小时（8 个 15 分钟区间均值）× `generator_1`/`generator_all`，
  长周期未来 24 小时（96 个区间均值）× 同两目标。
- 评分：官方指标为 1−MAPE；门槛为短期准确率 ≥90%、长期 ≥85%、总分 ≥60。
- 难点本质：以时刻 `t` 为起点的滚动预测，长周期要求在起点处一次给出未来 24 小时
  轨迹，而发电负荷受煤气产耗平衡、气柜水位与机组工况的多尺度耦合驱动，存在制度
  切换（台阶）与月份分布漂移（训练 5-9 月 → 测试 10 月上旬含国庆）。
- 详细：`docs/01_OFFICIAL_TASK_CONTRACT.md`。

## 2. 数据与标签

- 原始数据：4 个训练族（gas / gas_holder / gas_user / load，分钟级，2025-05-03 →
  2025-09-30）+ 4 个测试族（2025-10-01 → 2025-10-10），全部只读并 SHA-256 指纹封存。
- 已知数据缺陷（审计定位）：`blast_furnace_3`、`air_heater_3`、
  `blast_furnace_gas_holder_1`、`converter_user3` 存在全列空或晚投运；
  `converter_user1` 出现 -999 哨兵；训练/测试在 2025-05-01 存在重叠快照。
- 标签合同：以 15 分钟区间均值重构目标，共 14,496 个区间（14,494 完整），两个已知
  不完整区间（2025-08-27 18:00、2025-09-09 08:15）仅在实际量时排除。
- 修复的旧流程错误：旧方案以 15 分钟整点抽样代替区间均值、标签错位、错误排除已
  投运字段——这三项修复是 v3 链与旧版拉开差距的根源之一。
- 详细：`docs/02_DATA_GOVERNANCE_AND_AUDIT.md`、`docs/10_DATA_AUDIT_REPORT.md`。

## 3. 信息边界（合规核心）

- 预测起点 `t`：只允许使用 `t` 及以前已观测的过程量；官方答疑明确 `t` 之后的煤气
  发生、用户耗气、机组耗气、气柜状态即使存在于测试文件也属禁止未来信息。
- `t+15` 目标 = `[t, t+14]` 共 15 条一分钟负荷的均值，依次顺延。
- 工程实现：全部特征注册到 feature registry 并逐列标注 `causal` / `target_history` /
  `maximum_source_time_offset_minutes`；v3 链 622 个起点特征全部满足因果、最大来源
  偏移为 0，并通过"未来扰动不变性"单元测试。
- 详细：`docs/03_VALIDATION_PROTOCOL.md`、manifests/round2_v3/ 各 JSON。

## 4. 特征体系

| 层 | 内容 | 规模 |
|---|---|---:|
| 起点级全量特征 | 四族原始量的 lag / rolling / 日历聚合 | 622 个（因果注册） |
| 相似工况检索特征 | 21 个产耗平衡过程特征（产气、耗气、发电耗气、气柜、平衡代理的 level/delta/std） | 21 个 |
| 气柜边界特征 | 折内分位边界 + 贴边持续 + 多尺度逼近速度 + 平衡状态 → 固定权重压力分数 | 5 列 → 12 特征 |
| 共享 horizon 展开 | origin 特征 × horizon 编码 + 目标时刻日历 sin/cos/周末 | 96 行/起点 |

物理量守恒代理：`发生量 − 用户消耗 − 发电耗气 ± 气柜变化` 的闭合残差作为软特征
（不能构成严格等式，作为平衡代理使用）。

## 5. 验证设计（两代）

1. **6 折起点验证**（初期）：1,536 个验证起点，SHA-256 冻结切分。
2. **四个连续十日伪测试块**（主力，覆盖 3,840 起点 × 96 horizon）：7 月初、8 月初、
   BF3 投运期、九月下旬各 10 天；每块的训练库起点 `t+1440` 必须在块开始前完整结束，
   杜绝任何标签或过程量泄漏；已知缺失单元仅评分时排除。
- 设计动机：局部 pooled OOF 会掩盖近期折退化（首次平台校准 48.92 的直接教训），
  十日连续块强制暴露"工况制度切换下的稳定性"。
- horizon 分桶：near（15-120）/ mid1（135-360）/ mid2（375-720）/ far（735-1440）。
- 局限（收官认知）：10 个十日块在收官前全部用尽；本地验证对十月分布的判别力最终
  被证明不足（见 §9 结论 1）。
- 详细：`docs/61_ANALOG_TRAJECTORY_G1_PROTOCOL.md` §2（四块协议的最终权威表述）。

## 7. 实验管理与门禁

- 一次只改一个主要因素；每个 run 有唯一 `run_id`、不可覆盖 manifest（含全部输入/
  源码 SHA-256 指纹、环境、命令）、events.jsonl 与登记簿行；失败 run 保留。
- 组件晋级门禁（预登记后不得回改）：pooled 提升 ≥0.8 pct、最差十日块不退化、
  ≥3/4 块改善、near/far 两端安全（≥ -0.2 pct）、覆盖率/多样性达标。
- 平台提交纪律：每次只替换一个目标×周期区块，其余逐字节冻结；ZIP/CSV 全链 SHA-256；
  `verify_submission` 独立复核 960×17 / 960×193 结构、物理边界与 g1≤gall。
- 平台噪声认知：±0.1~0.2 分（由 shared gall 探针 -0.0082 等标定）。
- 详细：`docs/04_EXPERIMENT_PROTOCOL.md`、`docs/07_SUBMISSION_PROTOCOL.md`。

## 8. 工程保障

- 纯函数 + runner 分层：特征/指标/门禁逻辑全部为可单测纯函数；118 项 pytest 覆盖
  因果性扰动、哈希冻结、门禁方向、块布局校验等。
- 确定性训练：固定种子 + `deterministic=true`，同一配置复跑逐位一致
  （holder_2 确认实验的 crashed/completed 双 run 已实证）。
- 收官测试状态：**118 passed**。

## 9. 关键技术结论（供报告"结论与反思"）

1. **本地验证 ≠ 十月迁移**：五次平台探针中，本地 OOF 增益最高者（+1.50 pct）平台
   掉分最多（-0.74），呈负相关；根因是十月为持续高气柜制度（中位数比九月高 0.80
   IQR）且三号高炉 6.96% 取值低于全训练最小值（硬外推），本地十日块无法代表。
2. **最可靠的领先信号未被变现**：折内气柜边界压力与未来 24h 真实负荷变化的关系在
   8/8 个块稳定成立（pooled -0.44），但其对"控制模型残差"的修正方向随工况翻转，
   固定形状修正无法获益——机制真实、残差链接不稳。
3. **合规与归因纪律是护城河**：恢复列与过窄燃料窗曾触发 `cheat_detected` 的教训、
   事后取反信号被门禁拦下、五次探针全部单区块可归因——规程在多处以"少得分"的
   代价避免了不可复现与审计风险。
4. **可复现性的代价与价值**：v3 链最终未超过学弟的工程配方（63.46 vs 48.92 起点），
   但所有结论都有 run_id、哈希与逐位复现背书；官方"复现不出即撤销"的声明反过来
   证明了该纪律的竞赛价值。
5. 详细：`docs/12_PLATFORM_CALIBRATION_POSTMORTEM.md`、`docs/18_BREAK_65_RESEARCH_PLAN.md`、
   `docs/66`/`68`/`69`。
