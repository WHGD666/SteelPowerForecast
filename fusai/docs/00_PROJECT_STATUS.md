# 项目状态与阶段门禁

## 1. 项目目标

IronFlow 复赛要求预测钢铁企业煤气发电负荷：

- 短周期：未来 2 小时，15 分钟步长，共 8 步。
- 长周期：未来 24 小时，15 分钟步长，共 96 步。
- 目标：`generator_1` 和 `generator_all`。

当前官方历史最高分为 **52.4085**。项目首先需要达到 60 分有效成绩门槛，内部目标为 65+，但任何分数目标都不能以未来信息泄漏、不可复现或物理不合理为代价。

## 2. 当前阶段判断

按照竞赛实验生命周期，本项目当前处于：

> Stage 4：平台校准后的受控改进与历史机制复现。

原因：可复现 baseline、层次目标受控实验和首次平台提交均已完成。v3 baseline 平台总分
为 48.9241，低于历史 legacy v9 的 52.4085。当前任务不再是证明管线能运行，而是解释
本地验证与十月隐藏工况之间的泛化落差，并以单变量实验恢复有效机制。

## 5. 当前核心瓶颈

1. `generator_1` 是主要精度瓶颈，尤其是长周期。
2. 旧流程以 15 分钟整点抽样代替区间均值。
3. 验证真值存在一分钟或一个完整区间的错位。
4. 十月国庆工况与九月验证期存在分布变化。
5. 旧物理煤气平衡遗漏或错误排除了部分已投运字段。
6. v10 的真实未来路径增益属于 oracle 上界，不能代表可提交增益。
7. Sep 28–29 已用于多轮选择，不再是封存集。
8. 本地 pooled OOF 对十月工况代表性不足，近期折的退化曾被总体均值掩盖。
9. legacy v9 复现链不完整，当前无法将 3.4844 分差归因到单一组件。
10. 平台只返回总分；同时替换短期和长期文件无法形成高信息量实验。

## 7. 停止条件

出现以下任一情况，应停止继续调参并回到协议检查：

- 本地指标异常大幅提升但无法解释信息来源。
- 验证特征中出现预测起点之后的过程量。
- 标签时间段与官方示例不一致。
- 新旧 run 使用了不同切分却被直接比较。
- 平台高分对应代码或产物无法复现。
- 物理边界、目标组成关系或输出合同不满足。
- 总体指标改善但晚九月或投运工况显著退化。
- 提交同时改变短、长文件且平台总分无法支持归因。
- 候选未超过控制组却仅为“试试看”而消耗平台机会。
