# 验证协议 v3（baseline 冻结版）

## 1. 验证目的

验证必须回答的是：模型部署到一个新的滚动预测起点后，在目标列不可见、未来过程量不可见的情况下，能否稳定预测未来 2 小时和 24 小时。

验证不是为了制造漂亮分数。任何与正式推理信息边界不一致的验证结果都没有候选资格。

## 2. 验证单元

- 原始观测频率：1 分钟。
- 滚动起点频率：15 分钟。
- 每个起点产生：
  - 2 个目标 × 8 个短周期预测。
  - 2 个目标 × 96 个长周期预测。
- 目标值为对应未来 15 分钟区间均值。

## 3. 标签映射

对起点 `t` 和步长 `h=1..96`：

```text
label_start = t + 15*(h-1) minutes
label_end   = t + 15*h minutes - 1 minute
label       = mean(raw_target[label_start:label_end])
```

必须建立至少以下人工可核验测试：

- 10:00 的 t+15 等于 10:00–10:14 均值。
- 10:00 的 t+30 等于 10:15–10:29 均值。
- 10:00 的 t+120 等于 11:45–11:59 均值。
- 10:00 的 t+1440 等于次日 09:45–09:59 均值。
- 训练尾部不足 24 小时的起点只在标签完整时参与评价。

## 4. 信息边界模拟

每个验证折设定一个模型训练截止时间 `train_end`。必须满足：

1. 模型拟合样本的完整目标区间结束时间不晚于 `train_end`。
2. 对验证起点 `t`，特征只能来自 `timestamp <= t` 的过程观测。
3. 验证期原始目标列在推理状态中视为不可见。
4. 允许使用模型在更早验证起点生成的预测，但必须与正式滚动逻辑相同。
5. 填补器、异常阈值、缩放器、特征选择器和融合权重只在训练部分拟合。
6. 真实未来协变量只能用于评分后诊断，不能进入候选特征。

## 5. 切分策略

不使用随机切分。采用多个 expanding-window walk-forward 折，覆盖不同月份、负荷和生产状态。

切分日期已在完成首轮工况审计后冻结。逐起点清单保存在
`manifests/round2_v3/validation_origins_v3.csv`，其 SHA-256 单独保存；
仅修改 YAML 而不重新生成并审查清单，不构成新的有效协议。

冻结折覆盖的验证场景：

- 七月常规夏季工况。
- 八月常规高负荷工况。
- 九月初三号高炉相关字段投运后的工况。
- 九月中下旬明显降负荷日。
- 一号气柜投运后的晚九月工况。

共 6 折：前 5 折用于 v3 模型选择；Sep 28–29 为第 6 折，仅标记为
`consumed_development_only`。全部验证起点全局互斥，具体边界以
`configs/round2_v3/splits_v3.yaml` 为准。

Sep 28–29 已被旧实验多次查看和调参，只能作为开发验证时间块，不得重新命名为 sealed holdout。

当前没有真正未消费的内部封存集。平台测试是外部证据，但不得作为逐参数调优器。

## 6. 指标

### 主指标

- 短周期 pooled MAPE 和 `1-MAPE`。
- 长周期 pooled MAPE 和 `1-MAPE`。
- 分别报告 `generator_1` 与 `generator_all`。

### 必须保留的诊断指标

- 每个 horizon 的 MAPE、MAE、RMSE。
- 每折指标及折间标准差。
- 工况分层指标。
- 相邻 horizon 误差单调性违规数。
- 物理约束违规数。
- 零真值数量和处理方式。
- 每折样本数、有效标签数和缺失数。

本地可使用以下诊断综合量，但必须注明不是官方分数：

```text
local_accuracy = 0.5 * short_accuracy + 0.5 * long_accuracy
```

官方隐藏评分映射不得写入模型选择规则。

## 7. 候选选择规则

按以下顺序选择：

1. 无未来泄漏、输出合同正确。
2. 对比使用完全相同的标签和切分。
3. 短期与长期主指标提升。
4. `generator_1` 提升且 `generator_all` 不明显退步。
5. 提升在多数时间折和关键工况中成立。
6. 物理一致性和轨迹稳定性不恶化。
7. 差异很小时优先选择更简单、稳定、可复现的模型。

建议内部冲分门槛：

- 短期准确率目标不低于 91.5%，安全目标 92%。
- 长期准确率目标不低于 86%，安全目标 87%。

这些是工程目标，不是官方保证分数。

## 8. Oracle 与诊断实验

以下实验有价值，但不得与正式模型混淆：

- 真实未来 `generator_use_*` 输入。
- 真实未来煤气发生量与气柜路径输入。
- 使用真实历史目标滚动而不是模型预测滚动。
- 在完整数据上先拟合异常阈值再切分。

所有这类运行必须：

- `experiment_role: diagnostic`
- `submission_eligible: false`
- 在报告标题中注明“未来信息上界/不可提交”。

## 9. 验证协议 Gate

在运行 baseline 前必须自动证明：

- [x] 起点唯一且按 15 分钟递增。
- [x] 各折 validation 起点全局互斥，且 train 截止时间早于 validation。
- [x] 最新可用训练起点的 t+1440 区间结束不晚于训练截止时间。
- [ ] 每个特征的最大来源时间不晚于预测起点。
- [x] 已验证官方测试目标全空。
- [x] 短期 17 列、长期 193 列顺序正确。
- [ ] 指标人工样例计算一致。
